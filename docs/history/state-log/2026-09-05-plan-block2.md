## What this build does

1. Retires the 08-28 add flow whole: hover zone, pending row, MC + Work Card
   dropdowns, Add Item, the draft row's one-act placement (#77 §0: "anything
   built to the earlier two-dropdown flow is superseded").
2. Puts an ALWAYS-VISIBLE search field at the end of every sprint. Typing
   lists the matching addable work cards beneath it; each row has `Add`; the
   field row has `Add All`, which adds exactly the listed set in one request.
3. Three states per sprint, from the nodes: resting (placeholder, no Add All,
   nothing below) · matches (Add All blue-600, rows with a receded blue-300
   Add that rises with the label on row hover) · no matches (Add All grey,
   one muted line where the first result would be).
4. Server: a batch add route, so Add All is one act with per-row audit rows.

## Decisions (main thread, reversible, reported to JP at the gate)

- B1 **Query semantics**: trim, lowercase, split on whitespace; a card
  matches when EVERY token is a substring of its label `MC-NNN: <full name>`.
  The annotation's own example ("MC-06 Illustrate" → the five Illustrate
  cards) needs token-AND; a raw substring would miss the colon. Blank → no
  list, no Add All (resting).
- B2 **Order**: MC number ascending (mcRank; unrankable last, then string),
  then the server's own card order inside an MC (#73 provisional alphabetical
  — NEVER re-sorted client-side). No cap, no minimum length: the list on
  screen must BE the set; "M" listing every addable card is the honest
  output, raised with Miles.
- B3 **Add All = one batch request** with exactly the visible card ids, in
  list order. Server: sprint under project (404), each card checked under the
  project; already-scheduled / complete / gone cards are SKIPPED with a code,
  never fatal; created rows take tail positions in list order; ONE audit row
  per created row (same shape as the single add). Response 200
  `{ ok: true, added, skipped: [{ card_id, code }] }`. No confirmation, no
  count-check, no review pass (Miles). A banner only when something was
  skipped.
- B4 **After Add All**: the sprint's query clears iff `added ≥ 1` (the set was
  consumed; the field returns to rest). **After a single Add**: the query
  stays; the added card leaves the list when loadAll replaces the pool.
- B5 **Result rows land UNPLOTTED** (two acts, #72 §6). The result rows' and
  the search row's timeline halves are inert slate-50 with the week grid
  (the frame draws no + there, 840:31630). The draft-row one-act
  "commit and place" (old node 731:100277) retires with the pending row.
- B6 **Keys**: Escape clears that sprint's query (focus stays in the field);
  Enter does nothing (Enter-as-Add-All goes to Miles as a suggestion).
- B7 **No reflow**: search row 77 tall (16 + 45 + 16), result rows 54, in
  every state; the field FILLs and only its right edge moves when Add All
  appears (833:68629's rule). The row keeps the table's 1px slate-200 bottom
  rule in ALL states (the resting prose's "no visible stroke" contradicts its
  own only-the-width-moves rule; the grid wins).
- B8 **Two blues are tokens**: Add All `--blue-600`; per-row Add `--blue-300`
  at rest → `--blue-600` on `.gresult:hover` / `:focus-within`, together with
  the label → weight 600; disabled Add All `--slate-400`. No opacity anywhere
  on the links (Miles).
- B9 **Collapsed pane keeps the search row**: the field flexes to the 384px
  pane, labels ellipsis-clamp. The old hide existed only because the dropdown
  cells lived in hidden columns.
- B10 **State**: `addQ` is a map sprintId → string (one field per sprint,
  several may hold text); survives loadAll; resets on a project switch.
  `addBusy` (sprintId | null) makes THAT sprint's links inert for the flight;
  `sprintItemSaving` still guards placement.
- B11 **Pool unchanged**: `sprintItems.addable` stays MC-keyed and
  server-sorted (annotation: "FILTERING is unchanged"); the client flattens.
- B12 **Field typography**: the input is 14px Regular with the slate-400
  placeholder; it wears `.typed` (SemiBold slate-800) exactly when a panel is
  open for that sprint — CSS cannot read a value, the state can.
- B13 **The single POST keeps its optional `starts_on`** (a tested contract;
  nothing in this block sends it). Comments that cite the draft row's one-act
  placement (schedule.ts 451–462, sprint-items.test.ts 566–575) are
  rewritten, the contract is not. The batch route never takes `starts_on`.
- B14 **A shut block shows its header only**: the search row and its results
  sit inside the group's existing `collapsedBlocks` gate, exactly where the
  add zone sat (test/gantt-collapse.test.ts re-targets `.gsearch`).

## Frozen interfaces (frozen HERE and nowhere else)

### State keys (40-app-state.js data; F owns)
- `addQ: {}` — sprintId → query string. Two-way bound from the field.
- `addBusy: null` — sprintId while an add (single or all) is in flight.
- DELETE `addRow`, `addMenuFlip`; `addMenu` leaves OVERLAY_KEYS (60-overlays).

### Helpers (10-constants.js; F owns; main thread lists them in eslint FRONTEND_SHARED)
- `addLabel(mc, name)` → `${mc}: ${name}`.
- `addTokens(q)` → `string[]` (trim, lowercase, split on whitespace; `[]` for blank).
- `addMatches(q, addable)` → `Array<{ cardId, mc, name, label }>`; `[]` when
  `addTokens(q)` is empty; else every card in `addable` whose lowercased label
  contains every token; ordered per B2. Pure — no app access.

### Computed (40-app-state.js; F owns)
- `addPanels()` → `{ [sprintId]: { items: Array<{ cardId, mc, name, label }> } }`
  — a key exists ONLY for a sprint whose `addTokens(addQ[sprintId])` is
  non-empty (resting sprints are absent, so `{{#if addPanels[g.id]}}` is the
  resting/active switch — an EMPTY items array is still active: no-matches).
  Reads `sprints`, `addQ`, `sprintItems.addable`. Nothing else derives a list.

### Handlers (90-events.js; F owns)
- `addOne(_ctx, sprintId, cardId)` — POST `/api/projects/:pid/sprint-items`
  `{ sprint_id, card_id }` (the existing route). Guards: `addBusy` null and
  `sprintItemSaving` false, else return. Sets `addBusy = sprintId` +
  `sprintItemSaving = true` for the flight; 4xx → `flashBanner(errText(err))`;
  success → `loadAll()`. Query untouched. finally: both locks released.
- `addAll(_ctx, sprintId)` — ids = `addPanels[sprintId].items.map(cardId)`;
  empty → return. POST `/api/projects/:pid/sprint-items/batch`
  `{ sprint_id, card_ids }`. Success: if `added ≥ 1` → `app.set(\`addQ.${sprintId}\`, '')`;
  if `skipped.length` → banner "Added N of M — K already on the schedule / complete"
  (wording F's, one sentence); then `loadAll()`. Same locks as addOne.
- `addKey(ctx, sprintId)` — Escape → `app.set(\`addQ.${sprintId}\`, '')` and
  `preventDefault`; every other key falls through (Enter inert).
- `resetForProjectSwitch`: `addQ: {}`, `addBusy: null` replace `addRow: null`.
- DELETE: openAddRow, cancelAddRow, openAddMenu, pickAddMc, pickAddCard,
  addZoneKey, submitAddItem, draftPlace; the `'add'` plotRow branches; the
  toggleLeftPane draft discard; 80-loaders' add-draft invalidation block;
  60-overlays' `addMenu` key, shield, `.gddmenu` self-scroll entry and the
  Escape → cancelAddRow line.
