## Review rulings (main thread, 2026-09-08 — amend the frozen rules above)
- **Deadlines client skips excluded rows** (S-1/D-1): `dlBuild` treats `r.status === 'excluded'` like a missing start — not drawn, not counted, no load. The server keeps sending the row (Sprint Schedules still lists it).
- **Work spans** (S-3): in `worker/syncAres.ts`, an excluded lane counts as work in progress for the STARTED anchor (a move into any non-pending lane starts work) and never as done; `work_done_at` is held only while the current lane is a Done lane. No card loses a stored STARTED because its history passed through an ops lane.
- **Sprint membership follows the START day** (D-2): after a roll, `sprint_id` is the sprint holding the NEW start (`sprintFor(newStart, ranges)`), because the card's day is its start (§6.2). Reverses #75 §2's finish-day membership, which predates the start-day rule; reported to product at CLOSE. R-d2-q rewritten to match.
- **Excluded cards refused honestly** (S-5): the add routes answer 409 `CARD_EXCLUDED` / "That task card sits in a lane outside the pipeline — ops, discarded or unused — and cannot be scheduled." and the batch skip code is `CARD_EXCLUDED`; if the client maps skip codes to copy, the map gains the code with the same words.
- Guards for the two regex anchors (T-2, T-3); stale comments and docs (F-2, F-3, F-4, A-1, A-2, A-3, A-4, A-5, D-5) corrected.
