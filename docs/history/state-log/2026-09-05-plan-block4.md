## What this build does

1. Restores the URGENCY and DIFFICULTY filter axes — over WORK-CARD values —
   and the two PRIORITY sorts, in the frame's order and with the frame's labels.
2. Re-keys the two Deadline sorts on the EARLIEST work-card deadline (Miles).
3. Adds the two missing IDENTITY directions (ten sorts total).
4. Auto-opens groups whenever a work-card axis filters or a work-card-derived
   sort orders the table; hand-collapse survives until the trigger changes;
   childless MCs never open.
5. Narrows the children drawn inside an auto-opened group to the ones that
   match the live work-card axes (decision B3).
6. Keyless rows last in either direction, MC number ascending among themselves;
   equal keys fall back to the table's natural order (newest filed), then MC.
7. Search change returns the reader to the top (R-pf-h closed for search).

NOT in this build: ARES list position for STATUS order (backlog, own slice);
arrow-key walking inside the popovers (backlog); any server change; any CSS
geometry change (panels already match the frames); any owl.

## Decisions (main thread, reversible, reported to JP at the gate)

- B1 **Axis order = frame order**: TYPE · DIFFICULTY · URGENCY · STATUS.
- B2 **TYPE and STATUS read the MAIN row; DIFFICULTY and URGENCY read the
  work cards** (#78 §4 names only deadline/urgency/difficulty as work-card
  carried). Asked of Miles later whether STATUS should also read children.
- B3 **Child-level conjunction; non-matching siblings hidden.** A work card
  "matches" when it satisfies EVERY live work-card axis at once; a main row
  matches a work-card axis when at least one of its children matches; inside
  an auto-opened group only matching children are drawn. MC-825 has 99 work
  cards — showing all of them to find two urgent ones defeats the filter.
- B4 **Counts are counts of MAIN rows**, the row unit the table draws; NOT
  groups — on a shared MC every sibling row counts, so MC-825's 99 rows read
  "Urgent 99" with one urgent card (review 2026-09-05, finding C2; the word
  "groups" here was wrong). The ignore-own-axis arithmetic keeps working.
- B5 **Deadline sorts key on the earliest MATCHING child's `due`** (Manila
  day string, string compare); the parent's own BR-9 deadline is ignored, per
  #78 §2 ("main cards have no deadline at all"). Until block 3 empties the
  parent DEADLINE cell there is an interim mismatch; recorded, not fixed here.
- B6 **Priority aggregation**: Urgent first → any Urgent child = 1, all
  Non-Urgent = 0 (a VALUE), no matching children = keyless. Hardest first →
  max DIFF_RANK over labelled matching children, none labelled = keyless.
- B7 **Tiebreak** (5.B.4 confirmed as the build's reading, all ten sorts):
  keyless last both directions → MC ascending among keyless; equal keys →
  natural order (filedAt desc, never-read last) → MC ascending.
- B8 **STATUS stays alphabetical** (R-pf-e stands; the wire carries no list
  position). List order is an ARES read-API question → backlog.
- B9 **Sort button label stays `Group: Item`** — reads "Identity: MC Number:
  Low to High". The double colon goes to Miles as a question, not fixed here.
- B10 `pipeShut` overrides reset on every pipeFilters/pipeSort change; when no
  trigger is live, `expanded` (manual) is the whole truth again.
- B12 **(amendment, 2026-09-05 BUILD)** Facet arithmetic with BOTH work-card
  axes live. The frozen "unchanged arithmetic" under-counted: a group with an
  Urgent Easy card and a quiet Hard card fell out of both pools once Urgent and
  Hard were ticked, so Easy read zero on a panel where ticking it would widen
  the table — the exact "accurate and unusable" failure R-pf-c exists to
  prevent. Rule restated: the work-card axes are one conjunction, so they fail
  together and count as one failure; a row failing only that conjunction still
  counts in every work-card pool with its own-ignoring set. Found by the STATE
  agent (446/1000 random boards off the rule), reported not worked around; the
  main thread amended this file and applied the agent's validated patch
  (0/2000 boards off the rule). pipeMatches gets the matching definition of
  "except j".
- B11 Optimistic badge writes: `pipeKids` re-derives on the patched
  `workCardsByMc` keypath; row membership/order re-derive on the `loadAll`
  that already follows every write (block 1, F1). Documented, not fought.
