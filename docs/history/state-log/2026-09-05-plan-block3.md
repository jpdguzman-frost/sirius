## What this build does

1. **Deadlines on the work-card unit**: the tab becomes a view over the
   schedule's own rows (`sprintItems.rows`, already in the `/deliverables`
   payload): a card appears only when it is added to a sprint AND plotted AND
   has a forecast finish. Weeks of the selected month, each lane collapsed
   (cards stacked) or expanded (five day columns). Counts, progress line, the
   308×180 card with the four badge kinds, the Urgent quote bar, the 40% done
   card, the two dashed empty states. The old milestone tab — stats strip,
   banners, legend, search, conflict badges, acknowledge/restore, day-drag
   planner — is retired whole (ask 1 covers the acknowledgement half).
2. **Rollover** (server): after every ARES sync tick, every plotted, unfinished
   work card whose forecast finish has passed (Manila) moves forward one
   working day at a time until its finish is today or later; sprint membership
   follows the card's day; one audit row per moved card; no UI marker.
3. **Pipeline DEADLINE read-only**: main rows draw the em-dash; work rows draw
   the read-only date; both popovers leave Pipeline; W2's deliverable route and
   client branch are deleted; the contract's W2 scope narrows to the work card.
4. **The W2 setter on Sprint Schedules**: the DEADLINE cell of a work-card row
   carries the due-date popover (same recipe, same partial, same handlers),
   gated on `writesEnabled`; the reload re-derives the tick and `late`.
5. **Deadline inheritance retired**: a schedule row's deadline is its card's own
   Trello due date or none.

NOT in this build: the Apollo lane mapping (keyword `classifyList` stays as
JP's interim, #59); deleting the parked conflict/ack/day-plan server half; any
owl (CLOSE, on JP's word); block 5 (Requests) and block 6 (W4).

## Decisions (main thread, reversible, reported to JP at the gate)

- B1 **Data source**: the tab reads `sprintItems.rows` + `sprints` + `holidays`
  + `capacity.weekly` from the one `/deliverables` payload. The `/deadlines`
  fetch leaves `loadAll`; the route parks server-side with no caller.
- B2 **A card's day is its forecast FINISH** (`row.finish`). Rows without a
  finish (unplotted, no difficulty, card gone) are absent and never rolled.
- B3 **Weeks = the selected month's Mon–Fri weeks** — EXACTLY the set
  `lib/calendar.ts monthWeeks` returns (every week with a weekday inside the
  month; a straddling week shows under both months — amended after build, T's
  note: the earlier "Friday falls in the month" phrasing was looser than the
  executable rule),
  Manila month via `manilaToday()` + `monthOffset`. Navigator label = first
  shown Monday → month end: `Aug 31 – Sept 30, 2026`. Cards whose finish is
  outside the shown weeks are not drawn (month scope, as before).
- B4 **Counts**: pending = `status === 'pending'`, done = `'done'`, urgent =
  `urgent` (any status); ongoing counts in neither; the three are independent
  (#75 §1). Week header: Pending • Urgent • Done; day header: Pending • Done.
- B5 **Progress `N / C Work Cards`**: N = the week's cards (all statuses, a
  plain count), C = `capacity.weekly`; bar width = min(100, N/C·100)%.
- B6 **Card**: fixed 308×180; label `addLabel(mc, name)` clamped to 3 lines;
  badges in order: urgency (always: Urgent / Non-Urgent), difficulty (when
  labelled), asset (when the MC group agrees on ONE asset type), lane (the
  verbatim `currentList`, when present); links row: Trello, Figma (each when
  present). `.done` = opacity .4 on the card, nothing else restyled. `.urgent`
  = the quote bar, an inline SVG path (owl #74's path, verbatim) clipped by
  the card's own rounded box; the content inset is 18 on an urgent card, 14
  otherwise. Badge colours are tokens; Urgent is amber-600 (node; #79).
- B7 **Lanes**: collapsed = heading (Week N, range, chevron-circle) + progress
  + the week's cards stacked (day order, then row order) in a lane that
  scrolls vertically; expanded (one at a time, `expandedWeek`) = heading with
  the three counts + progress + five day columns Mon–Fri, each scrolling on
  its own, each with header (day name + two counts) and its cards. The week
  row scrolls horizontally in `.dlscroll`; the page body never does.
- B8 **Empty states from the nodes**: `None slated today` (day) / `None slated
  this week` (collapsed lane with no cards): a 310×104 white r4 card holding
  a 286×80 dashed [6,3] slate-200 r4 box, text 14px Regular slate-300 centred.
  The node's copy and tokens win over #74's prose and #80's pattern A;
  raised with Miles at CLOSE.
- B9 **Removals**: stats strip, alert-group + detail rows + acknowledged list,
  legend, search, week badges, capacity bar, day-drag planner, the "Reference
  only" note, the requestor chip. Conflicts, acks, `deadlines/day`,
  `MilestoneDayPlan` and their tests stay server-side untouched (ask 1).
- B10 **Rollover**: `rollUnfinished({ today })` in a new
  `src/services/rollover.ts`, called at the END of the worker's `aresTick`
  (after `runAresSync`, 15-min cadence; a card that went done in Trello is
  seen first). For every ongoing project: rows with `starts_on`, an active
  card with a difficulty, and `classifyList(current_list) !== 'done'`:
  `while (finish < today) starts_on = next working day` (`workday(d, 1)`;
  cap 400 steps), finish via `finishOf` (the engine, never a copy). Then the
  sprint holding the new FINISH day (`starts_on ≤ day ≤ ends_on`) becomes
  `sprint_id` (tail position) when it differs; no sprint covers it → the row
  stays listed where it is. Save; audit `sprintItem.rollover`, entity
  `sprint_item`, actor `system`, before/after `{ starts_on, sprint_id }`.
  Idempotent; catch-up after downtime in one pass; one log line.
  AMENDED after review (R3-1/2/3/5, R5-6): a project rolls only when its
  latest read (`ares` or `ares_push` sync_runs row) is ok and within 65 min;
  the move is a conditional `updateOne` keyed on the values read (a PM's
  concurrent write wins — `raced`); an audit failure takes the row back
  (`failed`); the step cap leaves the row (`capped`); per-row and per-project
  isolation; one `sync_runs` row per project per run; the result is the six
  counts `{ projects, moved, skipped, raced, failed, capped }`.
- B11 **Lane states**: `classifyList` keys pending/ongoing/done everywhere in
  this block (JP #59: it retires when the Apollo mapping lands — that slice
  needs Miles's group×type rule and an ARES read endpoint, neither here).
- B12 **Pipeline**: main-row DEADLINE = `<span class="dimcell">—</span>`;
  work-row DEADLINE = the existing `.datefield.readonly` span, unconditional
  (`overdue` / `missing` dress kept). Both `{{>dueCalendar}}` blocks and the

- B13 **Schedule cell**: `{{#if writesEnabled}}` the trigger + popover (the

  Trigger `on-click="['openDuePopover', row.cardId]"`; write →

- B14 **Inheritance retired**: `deadlineFor` = `card.trello_due ?? null`; the

- B15 **Project switch** resets `monthOffset: 0`, `expandedWeek: null`.
- B16 **Formats** (month table with the frame's `Sept`): navigator

- B17 **Server payload**: `SprintItemRow` gains `figmaUrl` and `assetType`

- B18 **Rulebooks at CLOSE** (main thread): new `deadlines-rules.md` (R-d2-*),
