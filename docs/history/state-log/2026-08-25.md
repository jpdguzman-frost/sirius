## The retired formula

The headline. The Forecast tab's Model Constants panel, as drawn in `279:22602`,
quotes *Total Cycle Time · 1.28 × Forecasted Review Time + 2.96*. Those are
`LEGACY_CYCLE` — the workbook regression that invariant 6 confines to
`lib/forecast.legacy.ts` and that SC-3 says is never exposed, because it
overstates review waits 2.6–4.6×.

Product's words: **it should never have been in that panel.** Building it
verbatim would have printed the retired model in front of a PM as if it were
live, on the one screen whose entire purpose is that the old model is gone. The
provenance guess in R-fc-d holds too — inherited from the old prototype's panel,
back when those numbers *were* the model. The replacement wording (which states
the shipped engine's relation, including the Review SLA override case) stands,
and product is fixing the frame so it cannot be copied forward again.

This is the second time a frame has carried a retired instruction that lapsed
without being retired — the `Open Card` underline in R-warn-r was the first. Both
were caught by measuring rather than by reading the annotation.

## The one code change

Everything else in #66 ratified what shipped. One item did not:

**The Pipeline table header said `Client`. Everything else said `Requestor`.**

Four surfaces speak this field's name — the table column header, the filter
panel's group heading, the indicator chip, and the Requests table's own column.
Three said Requestor. The header said Client, because node `70:10009` names
Client in its definitive column order and the table was built to it. The cell
*underneath* that header has rendered `row.requestor` since the day it was built.

Product ruled **REQUESTOR everywhere**, with a reason worth keeping: the values
are people, and on a single-client board a Client filter selects every row or
none — which is exactly why the axis was never built as one. The disagreement was
never cosmetic; it was one column labelled with a concept the product does not
have.

Renamed the label and moved the class with it (`col-client` → `col-requestor`,
six sites across the template, the stylesheet and one test). A class naming the
wrong noun is how the wrong noun finds its way back into the markup.

### The guard

Asserted as the rule, not as the fix. Every filter axis narrows a column the
table draws, therefore every axis label must appear verbatim in the header row:

```
it('names each filter axis exactly as its column header names it', () => {
  const axes = (recipe.PIPE_FILTERS as Axis[]).map((f) => f.label);
  for (const label of axes) expect(headings).toContain(label);
});
```

A sixth axis is covered without touching the test, and renaming the word in one
of the three places it is spoken fails here. Proved non-vacuous by reverting the
header to `Client` — two tests fail, both by name — then restoring it.
