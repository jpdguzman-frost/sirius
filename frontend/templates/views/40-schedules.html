{{! owl #31 (T153), re-seated on the run's own box by JP's structural ruling of 2026-08-18. The drag SOURCE is `.grun` — the coloured run's own box — not `.gbar`, and it is hit-testable at all times. Chrome hit-tests the draggable ancestor at dragstart and cancels the drag in the same tick when it cannot be hit; that was proven with real mouse input, which produced dragstart then dragend and nothing between. So `.grun` is solid in every state and OWNS its drop: `dragOver` (the same preventDefault the week cells use) plus `dropOnBar`, which maps the pointer's X to a week COLUMN through `weekAtX` and then runs the SAME `moveRows` recipe `dropOnWeek` runs — one write, one audit row. `.gbar` keeps its element and its class and goes back to `pointer-events: none`, which is the point of the whole change: outside the coloured run the track is transparent again, so the `.gweek` columns beneath get their drops back instead of a 1104px wrapper swallowing them. That is only safe because `.grun` re-declares `pointer-events: auto` — pointer-events inherits, and the child's explicit value beats the parent's. The box is one box over the WHOLE run, not one per segment: the segments touch, so it looks identical and the handle cannot flicker across a seam. It also carries a minimum grab width so a one-day phase is not a fiddly 18px target — the extra width is invisible, paints nothing, and is arithmetic rather than CSS. All the geometry comes ready-made out of `phaseRun` in 50-gantt-geometry.js: the box as a percentage of the TRACK, and each segment as a percentage of the BOX, already formatted.
